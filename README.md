# portfolio-builder

The product (**Foliocraft** — name set in `src/config/product.ts`): a landing page with pricing at `/`, checkout at `/subscribe` (30-day free trial, then Monthly or Yearly in ₹), and the workspace at `/admin` where each account builds its own portfolio.

- `/onboarding` — after signup (skippable, never a gate): basic details + profession, then designs for that profession with a live preview. Build portfolio then opens on a **For you** filter.
- `/admin/personal` — Personal information: profile, projects, experience, education, technologies and links, with a portfolio-strength checklist.
- `/admin/build` — Build portfolio in four steps (starting layout, sections, theme, footer) with a live preview of the real page.
- `/admin/billing` — trial countdown, pay for a plan, switch Monthly ↔ Yearly at the next renewal, cancel (access until the period ends) and resume. When a trial or plan ends, every admin page redirects here until a plan is chosen.
- `/admin/preview` renders the signed-in account's portfolio (accepts `?layout=` / `?template=` / `?theme=` / `?footer=` previews).
- `/p/:username` — a shared portfolio, public once its owner switches it on (Share dialog in the admin top bar). Section designs link to plain `/work/…`; the app redirects those under whichever portfolio the tab last showed (`src/lib/portfolioBase.tsx`).
- `/admin/users` — super admin only: every account, plan status, and activate/deactivate.

Talks to **portfolio-api** (`VITE_API_URL`); every request carries `?scope=mine` so it reads the signed-in account's data (or `?site=<username>` on a shared page). The published personal site is the separate **portfolio-site** repo.

`src/components/sections/variantCatalog.ts` is generated by `scripts/generate-section-catalog.cjs` on dev/build — add variants in the family source files, not in the catalog.

```sh
cp .env.example .env
npm install
npm run dev   # http://localhost:5174
```
